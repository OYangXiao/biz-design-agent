SECTION 01  /  统一认知语言 CLARIFYING AI CONCEPTS

很多人每天都在用 AI，却存在 3 个普遍误解

在讨论产品战略前，必须先划清大模型、上下文、MCP、Skill、Agent 与 Harness 的边界。

01
普遍误解 · MYTH
“我打开 Claude Code、WorkBuddy、DeepSeek Harness，就是在用 Agent。”
真实本质 · REALITY

你打开的其实是 Harness（宿主底座 / 未来 OS）

这些软件不是某一个单一业务专员，而是负责管理上下文记忆、权限隔离并统一调度各类插件的运行环境与工作台——真正的业务能力装在它内部的各个 Agent 里。

02
普遍误解 · MYTH
“我在对话框里不断喂资料、纠正它，是在‘训练’我的专属 AI 模型。”
真实本质 · REALITY

对话上下文只是会议室里的“临时白板”

日常对话从不会修改大模型参数。上下文窗口相当于电脑的临时内存（RAM），关闭窗口白板即擦除；真正让 AI 变专业且可复用的，是固化下来的技能手册（Skills）与记忆库。

03
普遍误解 · MYTH
“大模型、Agent、MCP、Skill / Workflow 听起来差不多是一回事？”
真实本质 · REALITY

它们分属大脑、专员、接口、手册 4 个独立层级

只有聪明的大模型就像招了一位“刚毕业的高材生”——没有 MCP 接口连不上柜台系统，没有 Skill 手册不懂合规流程，没有岗位授权（Agent）就无法独立交付业务结果。

TAKEAWAY券商不需要去重造“大脑”或“宿主底座”，而应专注打造宿主中最不可或缺的专业金融 Agent。

2025–2026 讨论焦点迁移 · X / REDDIT / 技术社区

大家在吵的不再是"哪个模型更聪明"，而是这六件工程活干得好不好——它们全部属于宿主层，与券商无关。

  • MEMORY跨会话长期记忆：记住客户偏好，而不是每次重喂一遍资料
  • STATE任务状态机：长任务可中断、可续跑，不必一次对话走完
  • SUBAGENT子 Agent 并发：一个主 Agent 派五个后台专员同时干活
  • SANDBOX权限沙箱：能碰文件、能跑代码，但碰不到不该碰的东西
  • COST上下文成本工程：裁剪、缓存、摘要，直接决定这门生意的毛利
  • EVAL评测与回归：意图 → 工具调用的准确率必须可测量、可对比
"模型是新的 CPU，上下文是新的 RAM；而真正被卷的，是跑在它上面的那套宿主工程。"
SO WHAT FOR A BROKER · 这六件事与我们的关系
不用自研记忆系统、沙箱、并发调度——宿主厂商会比我们做得更好、更便宜，且年年升级。
必须自建工具语义层、意图评测集、合规留痕。这三样没人替我们做，也做不了。
换句话说：宿主工程决定 AI 有多聪明好用，能力包工程决定它能不能真的替客户下单。前者我们无牌可打，后者我们握着一手好牌。

所以我们的结论是：不去造 OS，而去做宿主里最专业的那个垂直能力包

造宿主是千亿美金级、赢家通吃的战争，券商没有任何胜算；而官方投顾的价值恰恰落在编排层永远做不出来的四样东西上——牌照、柜台、数据与适当性判断。

SECTION 02  /  业界共识 II · 协议的三段式演进 MCP · SKILLS · PLUGIN MARKETPLACE

从"万物皆 MCP"到"MCP is dead"：一条被走完的炒作曲线

2023–2026 年，协议层走过了典型的三段：狂热、幻灭、收敛。看清这条曲线，可以帮我们省下两年学费。

① 协议狂热期2024–2025

万物皆 MCP：
把每个功能都包成插件

只要能调用就做成 Server，装机量等于把整本菜单一次打开；评测只看"接了多少个工具"。

  • 行为特征：工具越多越显专业，市场按数量排名
  • 隐藏代价：每次对话都要把全部工具说明书读一遍
  • 券商侧镜像：把 200 个柜台功能全部注册给宿主
当时的典型话语
"我们已经有 XX 个 MCP Server，生态覆盖最全。"——把工具数量当成了产品力。
事后回看
数量是可被一夜追平的优势，且每多一个工具，模型选错的概率就上升一点。
阶段结局上下文被工具定义占满，模型开始在相似工具间选错，Token 账单失控。
② 幻灭争论期2025–2026

"MCP is dead"：
上下文臃肿与 Token 爆炸

Reddit 与 X 上出现大规模吐槽：工具一多，匹配率反而下降；Skills 与按需加载开始取代"全量挂载"。

"装 40 个 MCP 之后，我花了更多时间纠正它选错工具。"
  • 核心矛盾：工具的发现成本 × 上下文占用 ≈ 反比体验
  • 认知转变：从"多即是好"翻转为"少即是快"
  • 技术应对：按需加载、工具分组、检索式发现开始替代"一次全挂"
争论的真实价值
它把行业注意力从"接协议"推回到"设计供给"——这正是券商最该参与的部分。
对券商的警示
如果我们的能力描述写得像一份"菜单"，无论用哪种协议，都会被这一轮淘汰。
阶段结局协议之争退潮，"该给模型看什么"取代"接了多少协议"成为核心命题。
③ 成熟收敛期2026 →

按需发现 ＋ MCP Apps：
只取当下需要的三五个能力

先检索发现、再按需加载；结果直接内嵌成可交互微界面（图表 / 表单 / 交易卡），上下文按任务裁剪。

  • 分发方式：从"装插件"变成"用时发现"
  • 体验分水岭：发现率 ＋ 内嵌交互，而不是协议兼容性
  • 券商侧动作：做能被一句话检索到的那 5 个能力，不做全量
  • 竞争新维度：描述质量 > 协议兼容性；场景覆盖 > 功能覆盖
判断标准
问自己一句：客户说"我港股又跌了"，我们的能力包能不能被第一时间取用？
交付物形态
一句可检索的能力描述 ＋ 一张可直接确认的交易卡 ＋ 一条完整的合规留痕。
阶段结局协议选择不再重要，"最小上下文 ＋ 内嵌可交互"成为生死线。
NOT THE POINT · 不重要的用的是 MCP 还是自家私有协议、接入了多少家宿主、Server 数量有多少——这些在 2026 年已经不是竞争维度。
THE POINT · 生死线能否被一句话检索到 ＋ 能否把结果直接变成可交互的交易卡 ＋ 能否把上下文压到最小。
STEP 01200 个柜台接口一次性注册给宿主
→
STEP 02首轮上下文被工具说明书吃掉三分之一
→
STEP 03客户问"港股盘口"却被调去两融开户
→
STEP 04多轮纠错、体验崩坏、成本双输

这不是模型不够聪明的错，而是供给侧的包装方式错了：把"功能清单"当成"能力描述"，宿主只能照单全收。

失败推演 · 量级示意（非严谨 benchmark）
200 个工具 × ~350 tokens = 7 万 tokens
单轮预算 20 万 → 首轮已占 35%
工具数 > 30 后选错率显著上升
每轮重付 → 手续费赚不回 Token 费
DESIGN RULE给宿主的不是整本菜单，而是"一句能检索到的五个招牌菜 ＋ 一张能直接下单的卡"。

SECTION 03  /  入口竞争 · WHO OWNS THE ENTRY POINT THREE CAMPS & OUR POSITION

谁会赢下"入口"？三种势力的博弈与我们的站位

入口之争不是"谁的 AI 更聪明"，而是"谁掌握调用发生的那一瞬"。三派各有必赢的战场，也各有结构性弱点。

CAMP 01 · PLATFORM OWNERS

操作系统原厂派

APPLE APP INTENTS / 安卓系统级 AGENT / WINDOWS
STRENGTH · 握有什么

开机入口、默认语音助手位、跨 App 调度与通知权限的最高优先级；用户不必安装任何东西。

WEAKNESS · 结构性弱点

跨生态中立性最差；金融深度几乎为零；对抽成与类目竞价有天然冲动。

SIGNAL · 现状信号

2025 年起开放三方"意图注册"，但审核与排序规则不透明。

TIME HORIZON · 时间窗

系统级挂载约 2027 年才对金融类目开放，此前入场是品牌预埋。

BARGAINING POWER · 议价力

渠道强、供给弱：类目满三家后，排序必然转向竞价与抽成。

SO WHAT · 对我们的启示

三家并行接、一套能力包、零定制分支——一次改造，多处复用。

WATCH OUT · 提防

索要"系统独有功能"者，直接放弃该单点。

我方动作做它们的合格供应商，绝不签独家；同一能力包同步上架多家。
CAMP 02 · MODEL & SUPER-APP

模型与超级客户端派

OPENAI / ANTHROPIC / 各家大模型桌面端
STRENGTH · 握有什么

最强推理能力与付费意愿最高的种子用户；上下文与工具调用的工程水平领先半年以上。

WEAKNESS · 结构性弱点

没有牌照、柜台与清算；荐股与交易的合规风险无法外包给他人。

SIGNAL · 现状信号

2025–2026 各家建"连接器市场"，金融类目却缺可执行的交易能力。

TIME HORIZON · 时间窗

最活跃用户集中于此，2026 年内形成默认调用习惯，先入者优势最大。

BARGAINING POWER · 议价力

与 OS 厂相反：他们需要我们的牌照与柜台，胜过我们需要它的流量。

SO WHAT · 对我们的启示

优先接用户最大、生态最开放的两家；差异点是"可执行"。

WATCH OUT · 提防

最易给真实收入也最易反悔：计价与退出条款进合同。

我方动作成为它们"自己不敢做"的持牌执行层，按调用与成交计费。
CAMP 03 · VERTICAL HARNESS

垂直 Harness 派

金融投研 / 开发工程 / 跨境电商 / 医疗
STRENGTH · 握有什么

工作流够深、客单价够高、巨头做不深；行业数据与合规门槛本身就是壁垒。

WEAKNESS · 结构性弱点

单一垂直天花板低；没有通用入口的流量；必须依附于前两派的宿主生态。

SIGNAL · 现状信号

2025 年多家垂直 Harness 拿到大额融资，验证深工作流付费意愿。

TIME HORIZON · 时间窗

金融垂直尚无赢家，窗口约 18–24 个月，之后被资质与数据锁死。

BARGAINING POWER · 议价力

对上是弱势渠道、对下是强势供给：只有客户离不开你时，价值才成立。

SO WHAT · 对我们的启示

先把能力格式、适当性字段、留痕要求写成事实标准，再谈生态。

WATCH OUT · 提防

标准谁都能用，先写的人定默认值。

我方动作这是主战场——也是唯一能由我们定义标准的地方。

结论与取舍：我们把"通用入口"让出去，只抢金融

判断通用生活入口会被 OS 厂垄断，因为它们握的是开机那一秒。
机会金融是高监管、高价值、强工作流的垂直入口，独立机会真实存在。
策略跨宿主中立 ＋ 只做能力包 ＋ 抢占"默认首选调用位"。
红线不签独家、不做某一家 OS 的深度定制分支、不做封闭生态里的专供版。
反向推演 · 如果押错边

只给某一家 OS 做深度绑定，等于把全部筹码押在别人换帅的那一天：份额不达标则能力白做，改规则则无议价权，客户换机则服务随之中断。

更致命的不是丢了开发费，而是品牌被降格成"某系统的内置功能"——再想以独立券商身份被客户记住，很贵。

对冲：能力包与宿主彻底解耦；私域与真人投顾网络兜住最后一段确定性。

POSITION不做某一家的功能，要做所有宿主都绕不开的那一层——这在入口时代是唯一可持续的位置。

SECTION 03  /  趋势分析 · TIMELINE & REVERSE RISKS 2025 → 2036

三段窗口与四个反向风险：什么时候必须已经站在场上

趋势不是用来预测的，是用来排期的。每段给出三样东西：市场信号、我们的动作窗口、错过会怎样。

2025–2026PHASE 01 · 形态收敛

协议与宿主形态收敛

这一段的胜负手不在产品，而在「接口是否已经可被外部调用」。

信号MCP 成为事实标准；几家 Harness 定型；插件市场出现真实流水而非演示
动作完成 Agent Gateway 与首个可被外部调用的能力包——本提案的编制即为此而设
指标网关语义工具数收敛到 12~15 个；首轮上下文占用 <20%；意图准确率 ≥90%
代价只能做被动"接入方"：能力何时被调用、排在第几位，全部由宿主的规则决定，我们连议价的资格都没有
2027–2029PHASE 02 · 挂载分发

系统级 Agent 挂载与 Marketplace 成型

这一段的胜负手不在技术，而在「类目里的位置与分成谈判」。

信号手机 OS 原生 Agent 开放三方能力；Marketplace 出现类目榜单、审核与抽成规则
动作3~5 个宿主同时在线，抢占金融类目默认位与首屏推荐位，用数据换排名
指标金融类目进入前三；被调用的意图覆盖主要业务；分成比例锁进合同而非口头
代价类目被两三家先发者占满，后来者只能持续买流量；且流量成本会随类目成熟逐步上涨
2030–2036PHASE 03 · 商业成熟

Agent 商业与计费体系成熟

这一段的胜负手不在规模，而在「按结果计费时你是否不可替代」。

信号按调用与按成交计费成为常态；Agent 之间出现代理议价；监管明确 Agent 荐股边界
动作从"卖权益"升级为"卖可被调用的执行能力"，按结果计费，嵌入客户工作流
指标非佣金收入占零售营收的可观比例；执行类调用成为主要成交入口
代价沦为纯通道：佣金被 Agent 侧持续挤压，客户认的是那个宿主，不再记得券商是谁
REVERSE RISKS · 四条反向风险与对冲
01模型能力跃迁，把"插件"价值整个吞掉
对冲：持牌、柜台、清算与适当性判断不在模型的能力半径内——这四样越强，我们越不可替代。
处置预留"能力包版本"开关：模型一夜变强时，我们能在一周内把重推理场景切给宿主，只保留执行与合规段。
早期信号 · 宿主开始用自家模型直连交易通道，或监管放开非持牌主体接入
02监管对 AI 荐股与生成内容收紧
对冲：只做客观筛选 ＋ 持牌研究所观点 ＋ 全链路留痕，先合规再智能，不做擦边功能。
处置建立话术红线库与双人复核；所有对外内容默认走"客观数据 + 持牌观点 + 风险揭示"三段式模板。
早期信号 · 出现针对"AI 生成投顾内容"的处罚案例，或投资者适当性指引更新
03客户不接受，仍愿意自己点
对冲：先给投顾与内部员工用，用服务半径的实测数据说服客户，再向 C 端放量。
处置每条新流程先跑投顾侧 A/B；用完成率、复访率两个硬指标决定是否向 C 端开放，不做全量强推。
早期信号 · 内测客群二次使用率低、主动切回 App 操作；语音输入占比始终上不去
04厂商抽成与类目竞价，把分发成本推高
对冲：私域 ＋ 真人投顾网络是唯一不必付"过路费"的渠道，必须与 Agent 渠道并重。
处置同步建设私域与投顾的直达路径；渠道预算设上限，超过上限即转向自有渠道，不让成本结构被单点绑架。
早期信号 · Marketplace 上线竞价位与包年套餐；头部能力位开始被两三家轮流买断
RESOLUTION趋势判断可以错，排期不能等——押一个"无论谁赢都需要"的位置，就是对冲。

5–8 人轻骑兵编制

不求人多，求六个角色齐。任一角色缺失，项目就会退化成一个"带对话框的客服页"。

AAgent 架构师 ×1：定网关边界、上下文预算与工具体系
B后端接口工程师 ×1.5：最熟悉公用接口的人，负责语义化改造
C投顾业务 Prompt/Skill 产品 ×1.5：把业务经验写成可执行 SOP
D交互设计师 ×1：只为"意图 → 卡片"设计，不为页面设计
E安全合规专家 ×1：适当性、留痕、话术审查，拥有否决权
FPM ×1：管口径与节奏，抵住"顺手加个功能"的诱惑
第 1–2 月网关骨架 ＋ 持仓/行情两段语义化，跑通第一个意图闭环
第 3–4 月接入交易与原语执行，评测集覆盖前 20 个高频意图
第 5 月起按业务切片扩面，每个切片带独立回滚点与验收口径
与现有 App 团队的关系：同源中台、双端并列，不吞并、不接管，共用账号、行情与柜台底座。
02 / COLLABORATION

和后台、合规、风控的协作机制

真正的难点从来不是模型，而是把一个为页面而生的接口体系，改造成可被 Agent 理解的语义层。

Agent Gateway 抽象层新增一层语义网关，把数十个碎接口收敛为十来个带描述的工具，页面侧零改动。
接口语义化改造排期按季度切片：先持仓与行情，再交易与两融，最后长尾业务；每个切片带独立回滚点。
留痕与拦截的责任划分网关负责记录全量调用与参数；合规模块负责适当性硬拦截与话术边界；模型层不承担任何合规判断。
风控联动异常调用频率、非本人设备、批量询价等信号回流风控，与现有反欺诈规则同池。
数据与行情授权Level-2、研报、指数等授权边界在网关层显式声明，避免模型越权取数。
一句话原则：能力可被模型调用，判断绝不能交给模型。
03 / CAPABILITY BUILD-OUT

四项必须自建的能力

这四样都不性感，但缺任何一项，线上表现都会变成"时好时坏的玄学"。

意图评测集把真实客户说法整理成回归测试集，测"意图 → 工具调用"的准确率，每次改动必跑。
上下文预算看板按场景盯 Token 成本与延迟，把每次对话的钱算到场景粒度，而非月度总账。
灰度与回滚能力包按客户分桶上线，任何异常可在十分钟内整体摘除，不必等版本发版。
留痕审计每一次建议、每一次确认、每一次拒绝都留档，可复盘、可举证、可对外解释。
双周复盘机制把线上失败案例回灌进评测集，形成"越用越准"的闭环，而不是越用越多补丁。
验收口径：没有评测集的功能不算做完了，只能算演示过了。

考核口径必须换：App 看停留，Agent 看完成

NEVER MEASURE AN AGENT BY TIME-ON-SCREEN
停留时长意图完成率 ↑
DAU / 打开次数交易笔数 ↑
页面 PV条件单渗透率 ↑
活动曝光量增值签约率 ↑
弹窗点击率AUM 留存 ↑
功能覆盖数被宿主调用次数 ↑
组织形式对比 · 两条路的终局
让 App 团队顺手做排期永远排在版本需求之后；产出必然是一个角落里的客服图标，考核沿用页面口径，越做越鸡肋。
独立特种小队（推荐）独立口径、独立预算、独立灰度权限；对上直接汇报，对下与 App 团队并列协作。
EXECUTION RULE考核什么，就会长成什么。拿停留时长考核 Agent，得到的必然是一个更会黏人的 App。
