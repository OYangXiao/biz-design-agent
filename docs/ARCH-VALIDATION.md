## 试点验收单

1. 两个不同团队分别提交原始资料。设计师只填[团队卡](TEAM-INTAKE.md)，核对提取的来源和适用范围；记录误读、追问与纠正次数。若仍需工程师手写每个团队的提示词，接入方案未通过。
2. 各选一个可重复主流程。按各自方法评审可点原型，并确认没有混入另一团队的组件、版本制度或文案。只有负责人签收才算真实试点通过。
3. 从其中一个已确认流程产出高保真源稿与一种演示。检查组件是真实例、稿件可编辑，演示引用的是已评审版本。业务方实际打开并完成观看或点击。
4. 在授权网页重复一次正确流程，再设置一个已知不符的预期，检查报告能给出相反结论及证据。与设计师选定同版本、同状态的设计屏，比较一个已知布局偏移；修复后复跑，旧报告与新报告都保留。
5. 记录耗时、人工纠正和返工点，比较原有办法。HTML、slides、视频任选已实现的一种，不因没有另外两种格式判试点失败。Computer Use 和宿主间移植分别标“未测”，直到有各自实证。
