# 角色四 · 测试（QA）与美工走查：页面功能验收与设计还原对图工作流

测试人员与美工走查环节**既可以紧接研发提测单发起，也可以完全独立发起**（例如拿着现成的预发 URL 和业务预期直接跑验收，无需先在本平台写 PRD 或生成设计稿）。

---

## 1. 模式五：页面功能验收与视觉对图对话菜单（含 `0. 退出当前模式`）

每轮操作后，Agent 先回显 `[当前模式：功能验收与视觉对图 · <构建号>]` 进度快照（功能通过/失败/未测条数、视觉像素差异数、累计验收轮次），再固定展示以下菜单：

| 选项 | 适用动作 | Agent 执行规范 |
|---|---|---|
| **1. 配置验收基准** | 指定授权测试 URL、构建号 Build ID、可复位测试数据、功能验收步骤及已签收 Figma 基准屏 | 缺少设计基准屏时**仅阻塞视觉对图，不阻塞功能验收**。 |
| **2. 执行隔离浏览器功能验收** | 启动隔离 Headless Chrome（`--headless=new` + 独立临时 profile）逐步点击、刷新、取无障碍快照与可见文案断言 | 严格区分三态：**已执行且符合 = 通过**；**已执行且不符 = 失败**；**缺环境/不可观测/构建号不匹配 = 未测**（绝不伪造通过）。 |
| **3. 执行设计还原像素对图** | 导出已签收 Figma Frame 同视口 1x 基准 PNG，与 Chrome 实测截屏比对 | 先做**连续两次截屏稳定性检查**（0 差异才进入对图）；支持记录动态区遮罩（Mask）及理由；宽高不一致直接报尺寸问题，绝不强行拉伸。 |
| **4. 生成综合报告与退回修复单** | 输出独立 HTML 可视化报告、JSON 证据包，并可选把走查对比卡与 `diff.png` 写入**Figma 独立走查副本页** | 严守双轨原则：**功能通过不自动让视觉通过；发布签字不交由模型代签；绝不改动已签收视觉源稿**。 |
| **5. 按新构建号在同一基准上复验** | 研发修复出新构建号后，用相同路径和相同视口基准复跑 | **旧轮次快照与差异图永久保留不覆盖**，形成「第 1 轮退回 → 第 2 轮通过」完整审计链。 |
| **0. 退出当前验收模式** | 退回研发修复或切换到其他角色模式 | 保存全部证据与轮次记录，退回**顶层主菜单**。 |

### 验收完成后的衔接菜单
> 1. **退回研发定位修复**（进入 [模式 4 · 研发联调](DEV-HANDOFF-WORKFLOW.md)，自动附失败步骤快照与像素差异包围盒）
> 2. **输入研发新构建号在同一基准复验**
> 0. **退出当前模式，返回主菜单切换其他角色或任务**

---

## 2. 执行命令

```bash
# 1. 从已签收 Figma 视觉页按 1x 视口导出基准 PNG
./fimg export --page "<视觉页名>" --names "<目标基准屏名>" --scale 1

# 2. 纯 Node 像素级视觉对图（零 Pillow，支持动态区遮罩）
./fimg visual-diff <基准.png> <实测.png> --out <差异热区.png> --threshold 8

# 3. 检查模式五验收菜单与轮次状态
./fimg qa menu-state <工作区>/qa-state.json
```
