业务交付课　/　从提需求到复测

一张退款单，
五个角色怎么接手？

假设你今天接手门店运营台。「让主管处理退款」听起来很简单。但客服能不能点？点完还能不能再点？这节课跟着同一张单，把这些问题变成能打开、能操作、能复查的结果。

01　/　先认人

按箭头走，点方框看交接

产品兼任模拟门店代表，设计、开发、测试各由独立 Agent 承担，带班人负责核对交付。下图是这次实际分工，不是要求每个团队都设五个岗位。

01 产品问清谁能点交需求单02 设计画出来给人试交原型、设计稿、演示03 开发做出测试页交各身份的入口04 测试换身份点一遍交快照、截图、问题单05 带班人核对再交付交结果和未测项

走不通怎么办？　测试指出哪一步不对 → 开发修新版本 → 测试用原单复查 → 才能收单。第一版不覆盖，留给下一位查。

02　/　跟着做

每个人到底交了什么

01产品

先问门店：「谁只看，谁能办？」

产品把门店的说法写进一张需求单，定下示例退款、按钮原文和四种情况。给设计和测试的是同一张表，谁也不用再猜「处理过的单还放不放按钮」。

看门店聊天、团队习惯和验收表 ↗
02设计

先试能不能办，再确认长什么样

交给产品：打开线框原型，点「批准退款」，看状态是否变成「已处理」。交给开发：以设计源稿为准看间距和按钮位置。交给门店：用分步演示讲给同事听。三份东西用途不同，不能拿演示当测试结果。

试点原型 ↗看设计源稿 ↗看业务分步演示 ↗
03开发

做一张可以换身份、换状态的测试页

开发拿同一张需求单和设计源稿做第一版。为了让培训能练到退回重做，这版有意留了两个错。你可以先只看需求，自己找，再和测试记录对答案。

第一版：当主管 ↗第一版：当客服 ↗
04测试

同一张单，不同人进来看到的一样吗？

测试先按需求单换四种情况，记下按钮有无；再以主管身份实际点击，重新读页面，不能只看点击前的截图。对图是另一件事：取同样的身份、数据和画面，比页面与设计稿，不拿第二版和第一版互相比来冒充设计验收。

展开看功能结果与对图 ↓
05带班人

先分清「改好了」和「还没测」

带班人把测试结果交回开发，确认用新入口按原条件复跑，再把原型、演示、两版页面和原始证据收在这本手册。可交的是培训样例；真实门店上线仍需要真实账号、后端结果和业务负责人签字。

第二版：当客服复查 ↗第二版：当主管复查 ↗

第一轮　·　退回开发

操作不该出现；按钮也低了 20 像素

客服虽点不动按钮，仍不符合「不显示」。另用主管身份比首屏：设计和页面有 13,983 个像素不同，集中在批准按钮附近。

第二轮　·　按原条件复查

客服入口消失；主管首屏对齐

不改需求，不换基准。两次截图确认画面稳定后再比，在这张 1280×800 首屏里，1,024,000 个像素中有 0 个不同。这不是所有设备都一样的证明。

看复测环境、时间和统计 ↗

流程也改了一条：别只写「下一班再打开」

设计师问：下一班是换身份，还是连设备也换了？第二轮开始前，我们在交接单上补明「在同一浏览器换身份重开」，并贴上测试版本、原图和重试入口。这次由另一位开发接单，QA 按相同数据重新验；跨设备和后台是否真实退款仍不写通过。

对照二轮交接单第一轮机器记录模拟业务代表如何复核

自己动手：先用客服查看，再以主管身份批准。本地页面会记住已处理结果；想从头练一次，请关闭原无痕会话，开一个新的无痕会话。此处的身份切换只是模拟，不是登录权限。

04　/　轮到你做

换到自己的项目，怎么用？

我是产品，要发什么给同事？

发一句目标、一个可用的例子，再写一个「谁不该做」的例子。能完整回答「谁、什么情况下、点哪里、变成什么」就够开工。

我是设计或开发，交接时发哪几个链接？

设计发可试流程的原型，以及标明哪一屏、哪一版的设计源稿。开发发测试页面、身份和测试单。别只发聊天里的截图让对方找版本。

我是测试，如何写一句可复查的问题？

「我以客服身份打开第一版待审单 R-17，不该出现『批准退款』，实际出现；这是入口和快照。」修好后用同样身份和数据重试，留下新版结果。

小练习：主管点完后看到「已处理」，就能收单吗？

还不能。看入口是否消失、换客服能否越过界面限制，并核对其余状态和设计位置。此处只测网页表现，生产环境还要另验服务端是否真的拒绝无权操作。
